# Architecture

## Maintained source

All functional changes belong in `src/neurodot/`. The root `Neurodot.py` file
is generated by `tools/build_monolith.py` and exists only as a convenient
single-file backup. Tests fail when it no longer matches the modules.

## Application flow

```text
Startup settings
    -> high-resolution series quality review
    -> confirmed exclusions moved recoverably
    -> Cellpose model initialization
    -> landmarks, exposure, channels, regions, and ROIs
    -> Cellpose batch detection
    -> Imaris-compatible output and display metadata
```

The quality overview uses full-resolution 2D MIPs. It starts on channel `g`,
supports `b`, `r`, and `405`, and applies display-only black `0` with an adaptive
white point constrained to `200..400`. Those overview values do not replace
counting exposure or exported Imaris display metadata.

## Module boundaries

- `config` and `paths` define state and locations.
- `image_io` and `imaris_io` isolate the file format.
- `detection` owns exposure arrays and Cellpose calls.
- `geometry` owns selection rules and coordinates.
- `quality_review` owns pre-analysis visual quality control.
- `gui` owns the main interactive annotation interface.
- `workflow` coordinates the stages without reimplementing them.

Keep file-format logic, geometry, and detection out of Tk event handlers where
possible. This lets the computational behavior be tested without opening the
full application.

## Release boundary

Model weights, donor `.ims` files, research data, logs, generated outputs, and
compiled artifacts are not source code and must remain untracked. Their rights
and metadata must be reviewed independently before any internal or public
distribution.
